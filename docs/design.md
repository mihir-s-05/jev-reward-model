# Design and interpretation

## What the comparison identifies

The primary substitution comparison is **grounded vs Jev terminal vs Qwen terminal**. They have identical sparse-reward locations, task streams and training implementation. The shaping comparison is **grounded vs grounded+Jev shaping vs grounded+Qwen shaping**. Comparing Jev shaping directly to Jev terminal changes both terminal ground truth and density; it does not isolate either factor.

A single frozen evaluator is reused across goals and structural families. This is deliberately weaker than testing arbitrary task domains: all tasks share one command language and transparent simulator semantics. Successful learning supports this narrow use case; it does not prove general-purpose reward modeling. No novelty claim is made for using LLM judges as rewards.

The actor receives all rules, a shuffled operation catalog, the finite turn budget and full factual interaction history. Ground truth is calculated from separately maintained sets/flags. The evaluator receives public evidence only. Receipts tell it what actually happened but do not provide the final success label. No narrative generated by the actor can fabricate a receipt. This is an evidence-grounded evaluator experiment, not a self-report grading exercise.

## Policy and critic

One sampled **complete command** is an RL action. Its probability is the product of its generated-token probabilities, including sampled EOS, or the capped token sequence if generation hits its limit. PPO therefore uses the **sum**, not the mean, of token log probabilities:

```text
log pi(command | history) = sum_j log pi(token_j | history, earlier command tokens)
ratio = exp(new_joint_logprob - frozen_old_joint_logprob)
actor_loss = -min(ratio * advantage, clip(ratio, 1-epsilon, 1+epsilon) * advantage)
```

This is command-level PPO, not token-level PPO/GRPO. Longer commands have more sensitive importance ratios; token caps, small updates, KL diagnostics and early stopping limit this issue. No top-k/top-p filtering, repetition penalties, constrained decoding or hidden output repair changes the actor's sampling distribution. Scoring uses exactly the sampling temperature. All generated action text, including malformed multiline responses, enters the simulator after ordinary whitespace trimming and special-token decoding.

`Qwen3_5ForConditionalGeneration` loads the real multimodal checkpoint. Only text is supplied; language Linear layers receive LoRA adapters, not the vision stack. The critic is a small scalar head on the final prompt hidden state. That position precedes action tokens; causal processing prevents answer leakage. Actor and critic share the adapted backbone, but Jev is never substituted for the policy-dependent value function.

A single backbone forward yields both action likelihood and the prefix value. The large vocabulary projection is restricted to response positions and checkpointed in small chunks. Generation batches active episodes; PPO accumulates one-command microbatches into a minibatch optimizer step. Rollouts retain unpadded CPU tokens, not GPU graphs. Gradient checkpointing and zero dropout are explicit. No throughput or VRAM claim is made before measurement.

Complete finite-task episodes supply GAE:

```text
delta_t = reward_t + gamma * old_value_(t+1) - old_value_t
advantage_t = delta_t + gamma * lambda * advantage_(t+1)
return_t = advantage_t + old_value_t
```

At the true task horizon or explicit finish, bootstrap value is zero. A turn budget is part of the task; the collector does not truncate an otherwise continuing MDP and pretend termination. Advantages, not rewards, are normalized across the rollout batch. Returns stay in original units. The critic uses clipped value regression. Approximate behavior KL and clip fraction are logged. Nonfinite values and extreme likelihood ratios abort instead of being silently clamped into plausible results.

There is no fictitious entropy coefficient. Optional `reference_kl_coef` subtracts a sampled initial-model log-ratio reward, with adapters disabled for reference scoring. Its default is zero to isolate reward-source substitution. A reference penalty changes the optimized objective; apply the same coefficient in every matched arm.

## Potential shaping

For state potential Phi supplied by either judge:

```text
shaped_reward_t = grounded_reward_t + alpha * (gamma * Phi_(t+1) - Phi_t)
Phi_terminal = 0
```

Jev's progress question has five descriptions spanning zero to all required operations applied; the returned expected level index is divided by four. A forbidden action should collapse potential to zero. Complete operations before FINISH may have high potential but do not yet receive grounded terminal success.

Every boundary potential is evaluated once per episode and reused consistently in adjacent transitions. Terminal potential is mathematically zero, not a judge prediction. The discounted shaping sum telescopes to `-alpha * Phi_initial`, so the complete-trajectory objective differs only by an initial-state offset. With exact transformed values, advantages are unchanged. Any benefit is an empirical effect on approximate value learning/finite-data optimization, not newly created causal information. Incorrect potentials can make learning worse even though the terminal-objective argument holds.

Potential queries see only the corresponding history prefix. Terminal judgments are made only after the episode. No final trajectory is fed back as a supposedly online value estimate. Context-view ablations include turn counts and omission metadata so absent evidence is not silently represented as complete evidence.

## Evaluator interface and stability

Jev requests follow the documented `state`, `model`, `questions` contract. The terminal question reads the returned `noul`; progress reads probabilities over ordered levels and checks their legend and expected score. `confidence` is never multiplied into rewards or mistaken for correctness probability. Qwen receives the same semantic rubric and returns schema-constrained numerical estimates; these are verbalized probabilities and need calibration testing.

One persistent HTTP client, bounded worker pool, and per-run SQLite cache overlap evaluator calls. Cache keys include the complete payload, model/endpoint/revision, rubric and environment version. Identical requests are deduplicated within a batch. Responses must have finite probabilities, valid level mass, model identity and token usage. Only validated responses enter the cache. Missing usage is not priced as zero. Transient failures retry with bounded backoff; permanent/API/schema failures abort the batch. No fallback oracle, failed-episode filtering, or zero-on-error reward changes the experiment.

A run records returned model strings and stops on a changed string. **An unchanged `jev-latest` string does not prove unchanged weights.** The public API does not expose a guaranteed immutable underlying revision in this implementation. Run matched arms near each other, preserve timestamps/raw responses, and request a pinned model from the provider if available. Do not reuse another study's cache as if it were a fresh service measurement. Resume copies only that run's cache.

The Qwen server is independent of the trained adapter. Its configured revision is a user assertion about deployment, not a value passed to inference to change weights. Save the server launch configuration and package version. Its local token usage is not an API invoice; account for serving-device rent separately.

## Evaluation protocol

Use one fixed dataset and equal planned rollout/update budgets across seeds. Defaults train on three dependency families and validate on different instances. Structural and length tests remain untouched during selection. Start with the base actor and judge-only counterexamples; a ceiling/floor task is not rescued by a larger training run. Adjust difficulty only using a development protocol, regenerate all matched splits once, then freeze them.

Report exact success, irreversible violations and completed-operation fraction. Training logs retain both proxy reward and ground truth even when ground truth is hidden from optimization. Inspect late-policy high-score failures; initial offline judge accuracy alone does not measure reward overoptimization. Audit scripts include missing work, no finish, old forbidden actions, rejected dependencies, and prompt-injection-style narration. Their synthetic class balance is artificial; calibration on those cases is not a deployment calibration estimate.

Use at least the provided three seeds before drawing comparative conclusions, and treat their uncertainty as provisional. The report's standard error is across seeds; tasks/trajectories within a seed are not independent replicate experiments. Structural test families and longer trajectories are limited transfer probes, not proof of generality.

The reporting script aligns only **already completed** validation checkpoints at common observed budgets. Curves are step-held, not interpolated using a later checkpoint's score. Config/data mismatches fail, and resumed segments cannot masquerade as new seeds. The final test evaluator reports per-family and per-horizon results, while learning curves are validation curves. Analyze test results only after the experimental choices are fixed.

## Artifacts and accounting

| Run artifact | Contents |
|---|---|
| `resolved_config.yaml`, `manifest.json` | Full settings, actor revision, source/data fingerprints, packages, GPU |
| `rollouts.jsonl` | Exact sampled prompt/action tokens, old likelihoods/values, raw evidence, before API calls |
| `train_traces.jsonl` | Rewards, potentials, terminal judge scores, grounded outcomes, complete history |
| `train.jsonl` | PPO metrics, success, separate task/objective returns, cumulative counters and times |
| `validation*.jsonl` | Held-out deterministic success and complete validation traces |
| `judge_requests.jsonl`, `judge_cache.sqlite3` | Payloads, responses, parsed values, timing/cache status |
| `checkpoint-*`, `latest.json` | Adapter, critic, optimizer/RNG/config/accounting snapshot, latest pointer |
| `accounting.json` | Final counters even after an evaluator error |

No API credentials are put into configs or request logs. Trace files can be large; they are intentionally excluded from git. In this synthetic study they contain no real customer data. Do not send sensitive real-world trajectories to a provider without appropriate authorization and data handling.

Billed token counters count successful uncached validated requests; replay counters include cache reuse across calls. In-batch deduplication is one evaluation, not multiple billed requests. Concurrent summed request-seconds are not wall time: `reward_seconds` measures the actual evaluator phase. Failed/retried calls can have unknown billing; accounting flags that uncertainty, and failed raw response bodies are retained for review.

User-supplied hourly rates yield reserved-device estimates including model load, actor work, evaluator waits, and validation. They do not include separately performed offline audits, server initialization before the run, storage, or idle gaps between processes. Charge those separately in a complete study invoice. CUDA synchronization brackets GPU phases. Exact bitwise reproducibility across kernels/hardware or changing hosted models is not promised.
